### 软件接口

**1. ****操作系统接口 (Operating System Interface)**

系统需实现应用层与底层操作系统的无缝交互，确保多平台兼容性与高可用性。

* **服务端操作系统接口：**

o   **运行环境：** Linux (Ubuntu 20.04 LTS 或 CentOS 8 及以上版本)。

o   **文件系统交互：** 系统通过标准的 POSIX 文件系统 API 进行日志写入、临时文件暂存和静态资源读取。

o   **服务管理接口：** 系统需支持通过 systemd 守护进程进行启停、重启和状态监控。应用程序的异常退出需能触发 Linux 系统的自启机制。

* **客户端操作系统接口：**

o   **运行环境：** 客户端不直接调用桌面或移动端操作系统 API，完全通过符合 W3C 标准的 Web 浏览器（如 Chrome, Edge, Safari）进行安全隔离运行。

o   **浏览器兼容性检验：** 系统前端需通过标准浏览器内核提供的 DOM 接口和 BOM 接口进行渲染，确保在主流浏览器中无排版错乱和功能缺失。

**2. ****数据库接口 (Database Interface)**

系统与数据存储层之间的交互需保证数据的一致性、完整性和高效性。

* **数据库版本：** MySQL 8.0 关系型数据库。
* **访问驱动与连接池：**

o   服务端采用 JDBC (Java Database Connectivity) 标准接口，并结合 HikariCP 连接池进行连接管理。

o   数据库连接参数必须配置支持 UTF-8 字符集（utf8mb4）和时区同步（serverTimezone=Asia/Shanghai）。

* **核心业务表设计与约束规范：**

o   **事务支持：** 核心业务表（如签到记录表、用户权限表）必须指定存储引擎为 InnoDB，以支持 ACID 事务特性（特别是原子性与隔离性）。

o   **索引优化：** 高频查询字段（如学号 user\_id、课程号 course\_id）必须建立 B+Tree 索引。复合查询需建立联合索引，确保查询效率，单条索引查找响应时间小于 50ms。

o   **状态字段约束：** 状态类字段（如签到状态：0-未签到、1-已签到、2-迟到）必须在数据库层设置非空（NOT NULL）与默认值（DEFAULT）约束，并在应用层通过枚举类（Enum）进行严格映射检验。

**3. ****外部服务接口 (External Service Interface)**

系统与第三方云服务及模拟环境的通信需遵循统一的协议与流控机制。

* **邮件/SMS ****消息通知接口：**

o   **邮件服务 (SMTP)****：** 采用标准 SMTP 协议，通过 465 加密端口（SSL/TLS）与第三方邮件服务器（如网易 163、腾讯企业邮）连接。数据交互格式为标准 MIME。

o   **短信服务 (SMS API)****：** 采用 HTTPS 协议，通过第三方（如阿里云/腾讯云 SMS）提供的 RESTful API 接口发送验证码或通知。数据格式为 application/json，必须包含签名（Signature）与时间戳（Timestamp）校验。

* **支付结果接收接口：**

o   **第三方正式/****沙箱回调：** 采用 HTTP/HTTPS POST 异步回调机制。系统必须开放公开的 Webhook 端点（如 /api/v1/payment/callback）以接收支付平台发来的 XML 或 JSON 格式的支付结果通知。

o   **模拟接口：** 在演示或测试环境下，系统需提供独立的模拟支付控制台接口，通过内部 Mock 服务直接更改订单状态，模拟完整的支付闭环。

o   **安全性校验：** 对所有外部回调接口，系统必须进行签名验签（基于 RSA 或 MD5 加密算法），防止伪造回调攻击。

**4. ****开发框架接口 (Development Framework Interface)**

本系统采用前后端分离的现代化软件架构，以方便团队高效分工开发与模块解耦。

* **前端框架 (Vue.js)****：**

o   前端通过 Axios 组件作为唯一的 HTTP 客户端向后端发起请求。

o   全局拦截器（Interceptors）规范：请求拦截器负责在 HTTP Header 中统一注入 JWT（JSON Web Token）鉴权令牌；响应拦截器负责统一处理 401（未授权）、403（拒绝访问）、500（服务器错误）等状态码。

* **后端框架 (Spring Boot)****：**

o   后端采用 Spring Boot 构建 RESTful API 架构，通过 @RestController 注解向前端暴露服务。

o   **数据传输对象 (DTO)****：** 前后端交互的数据必须封装在统一的响应结构体中，其纯文本 JSON 格式规范如下：

JSON

{

"code": 200,

"message": "操作成功",

"data": {

"user\_id": "STU-10024",

"status": "success"
}

}

* **跨域资源共享 (CORS) ****接口：**

o   后端框架必须配置 CORS 策略（如使用 @CrossOrigin 或注册 CorsFilter），显式允许来自前端开发环境域名及端口的请求，并对请求头（Allowed Headers）和请求方法（Allowed Methods: GET, POST, PUT, DELETE）进行精确白名单限制。

### 4.4.3 通信接口

**1.** **浏览器通信接口 (Browser Communication Interface)**

用于保障前端浏览器客户端与后端应用服务器之间高效、安全的常规数据交互。

* **应用层协议：** HTTP/1.1 与 HTTP/2。
* **安全传输层协议：**强制采用 HTTPS (TLS 1.2 或 TLS 1.3) 加密传输，禁止一切明文 HTTP 请求。后端服务器需配置 HSTS（HTTP 严格传输安全）策略。
* **网络端口：** TCP 443 端口。
* **架构风格与交互模式：** \* 采用标准的 RESTful 架构风格。通过标准的 HTTP 谓词（GET、POST、PUT、DELETE）明确定义资源的操作行为。
  * 状态码规范：请求成功返回 200 或 201；客户端认证失败返回 401；权限不足返回 403；资源不存在返回 404；服务器内部错误返回 500。
* **数据交换格式：**请求体（Request Body）与响应体（Response Body）格式严格限定为 application/json，字符集统一为 UTF-8。

**2.** **通知通信接口 (Notification Communication Interface)**

处理系统内部的即时消息分发以及面向用户的外部渠道通知，采用动静分离、同步与异步结合的机制。

* **站内消息中心通信（同步机制）：**

o   **业务逻辑：**当系统触发通知事件（如签到成功、活动发布）时，系统需在同一次事务中同步调用本地持久化接口，将消息直接写入数据库的消息中心表（Message Center）。

o   **实时推送协议：**针对在线用户，系统应支持通过 WebSocket 协议（端口: TCP 443 或专属端口 TCP 8085）将消息中心的新消息实时推送到前端浏览器，避免客户端轮询。

* **邮件/****短信通知通信（异步机制）：**

o   **异步架构：**为防止邮件或短信发送延迟导致的主线程阻塞，系统必须引入消息队列（如 RabbitMQ 或 Redis Queue）或线程池进行异步解耦。

o   **通信流程：**主业务逻辑完成存盘后，将通知内容发布到专属交换机或队列中，由后台异步监听线程（Worker）负责消费消息并调用第三方外部接口（SMTP服务器或短信网关）。

o   **容错与重试：**异步通信接口必须具备失败重试机制（默认重试 3 次，间隔 5 分钟），重试失败后自动记入异常日志并触发管理员告警。

**3.** **文件传输接口 (File Transfer Interface)**

规范活动附件、投稿图片等文件上传的通道，保障服务器存储空间的安全和可追溯性。

* **传输协议与方法：**采用 HTTPS 协议，HTTP 请求头中的 Content-Type 必须指定为 multipart/form-data。
* **网络端口：** TCP 443 端口，若对接第三方对象存储（如阿里云 OSS、腾讯云 COS），则遵循云厂商提供的专属 API 域名及外部公网端口。
* **文件安全性限制与检验标准：**

o   **图片上传限制：**格式仅允许为 jpg、jpeg、png、gif；单张图片大小限制小于或等于 5MB。

o   **活动附件上传限制：**格式仅允许为 pdf、docx、xlsx、pptx、zip、rar；单个文件大小限制小于或等于 50MB。

o   **后端校验防伪：**后端程序禁止仅通过文件后缀名进行判断，必须读取文件流的前几个字节（File Signatures/Magic Number）校验文件真实 Mime-Type，严防上传恶意脚本木马（如 .php、.jsp 文件）。

* **追溯与审计规范：**

o   **参数绑定：**每次文件上传请求的 Header 中必须携带当前登录用户的有效身份令牌（JWT）。

o   **数据库记录：**后端在接收并保存文件成功后，必须将文件的物理/云存储绝对路径、文件原始名称、生成的新名称、文件大小、上传时间以及上传人用户唯一标识（user\_id）和上传时客户端 IP 地址同步写入系统文件审计表。
