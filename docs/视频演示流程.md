# 志愿者服务管理系统 3-4 分钟视频演示流程

本文档用于录制 3 到 4 分钟课程验收演示视频。推荐按“志愿者发起业务 -> 管理员审核处理 -> 平台统计审计”的主线录制，不要在短视频里平均展示所有页面，否则会像逛菜单，业务闭环不够清楚。

## 1. 录制前准备

录制前不要展示终端里的数据库密码、邮箱授权码或 `.env` 文件。

1. 确认后端、前端、MySQL 已启动。
2. 确认浏览器能访问 `http://127.0.0.1:5173`。
3. 建议把浏览器缩放调到 `90%` 或 `100%`，避免页面底部按钮被挡住。
4. 建议从项目根目录进入 MySQL 客户端后重置样例数据：

```sql
SOURCE backend/src/main/resources/sql/demo-data.sql;
```

5. 打开浏览器无痕窗口或先退出当前账号，进入 `/login` 页面。
6. 录制时准备两个账号：

| 角色 | 用户名 | 密码 | 用途 |
| --- | --- | --- | --- |
| 志愿者 | `linan@example.com` | `volunteer123` | 展示活动报名、我的报名、服务记录和更正申请 |
| 管理员 | `admin@example.com` | `admin123` | 展示报名审核、服务记录更正审核、通知、统计、审计 |

说明：`demo-data.sql` 中林安已有“社区图书馆阅读陪伴”的服务记录和待审核更正申请，同时还可以报名“校园迎新志愿服务”，适合串成一条清楚的演示主线。

## 2. 推荐总时长

建议目标时长：`3 分 30 秒` 到 `3 分 50 秒`。

| 时间段 | 页面 | 演示重点 |
| --- | --- | --- |
| 0:00-0:20 | 登录页 | 说明系统角色和样例数据 |
| 0:20-0:55 | 活动 | 志愿者查看活动并报名 |
| 0:55-1:20 | 我的报名、服务记录 | 查看报名状态和服务记录更正申请 |
| 1:20-1:40 | 切换管理员 | 体现角色权限分离 |
| 1:40-2:20 | 活动执行 | 审核报名，展示签到码和报名状态流转 |
| 2:20-2:55 | 服务记录 | 审核服务记录更正，展示 v4 纠错闭环 |
| 2:55-3:25 | 通知、统计 | 展示通知任务和运营看板 |
| 3:25-3:45 | 审计日志 | 展示关键操作可追溯，收尾总结 |

## 3. 正式录制流程

### 3.1 开场与志愿者登录，约 20 秒

操作步骤：

1. 打开登录页。
2. 输入 `linan@example.com / volunteer123`。
3. 点击“登录”。

讲解词参考：

> 这是志愿者服务管理系统，支持志愿者、组织方和管理员三类角色。当前视频使用样例数据，先从志愿者视角进入系统，展示活动报名、服务记录和后续审核闭环。

画面要点：

- 顶部显示“林安”“志愿者”“积分”等信息。
- 导航栏中没有“用户管理”“审计日志”等管理员入口，体现权限隔离。

### 3.2 志愿者查看活动并报名，约 35 秒

操作步骤：

1. 进入“活动”页。
2. 在“状态”筛选中选择“报名中”，点击“查询活动”。
3. 找到“校园迎新志愿服务”。
4. 简要展示活动地点、报名截止时间、人数上限、参与要求。
5. 点击“我要报名”。
6. 等待页面提示“报名成功”。

讲解词参考：

> 志愿者可以按关键字、地点和活动状态筛选活动。这里选择报名中的校园迎新活动，系统会展示时间、地点、名额和参与要求。点击“我要报名”后，报名进入待审核状态，后续由组织方或管理员处理。

录制注意：

- 如果之前已经点过报名，按钮可能会返回重复报名错误。重新录制前执行一次 `demo-data.sql`，或者直接跳过点击报名，改为在“我的报名”中展示已有待审核记录。

### 3.3 查看“我的报名”和服务记录，约 25 秒

操作步骤：

1. 点击导航栏“我的报名”。
2. 展示刚才的“校园迎新志愿服务”处于“待审核”。
3. 展示页面中其他已完成活动记录，说明已通过、已完成、已取消等状态均以中文显示。
4. 点击导航栏“服务记录”。
5. 展示“我的服务记录”和“服务记录更正申请”。
6. 指出林安已有一条“社区图书馆阅读陪伴”的服务记录和待审核更正申请。

讲解词参考：

> 报名后，志愿者可以在“我的报名”中跟踪审核状态、签到签退状态和活动评价。服务结束后，服务记录会沉淀到个人档案；如果服务时长或成果描述有误，志愿者可以提交更正申请，审核通过后系统会同步修正记录和积分。

### 3.4 切换到管理员账号，约 20 秒

操作步骤：

1. 点击右上角“退出”。
2. 输入 `admin@example.com / admin123`。
3. 点击“登录”。

讲解词参考：

> 接下来切换到管理员视角，展示后台如何审核报名、处理服务记录更正，以及如何通过通知、统计和审计保证业务可追踪。

画面要点：

- 管理员登录后导航栏出现“活动执行”“统计”“系统运维”“用户管理”“审计日志”等入口。

### 3.5 管理员审核报名，约 40 秒

操作步骤：

1. 点击“活动执行”。
2. 在“选择活动”中选择“校园迎新志愿服务（报名中）”。
3. 展示“自助签到码”，例如 `HELLO26` 或刷新后的签到码。
4. 找到刚刚报名的“林安”记录，状态应为“待审核”。如果林安没有出现，可审核样例数据中原本待审核的“刘琪”。
5. 在“报名审核/取消说明”中输入：`符合活动要求，准予参加。`
6. 点击该报名记录后的“审核通过”。
7. 等待提示“报名审核通过”。

讲解词参考：

> 管理员和组织方可以在活动执行页面处理报名审核。系统会记录审核说明，并把报名状态从待审核流转为已通过。活动还维护自助签到码，后续志愿者可在“我的报名”中输入签到码完成签到或签退。

录制注意：

- 这一步会改变数据状态。若要重录，请重新执行 `demo-data.sql`。
- 如果点错“驳回”，不要继续硬录，直接重置样例数据再来一遍。

### 3.6 审核服务记录更正，约 35 秒

操作步骤：

1. 点击“服务记录”。
2. 滚动到“服务记录更正审核”。
3. 找到林安针对“社区图书馆阅读陪伴”的待审核更正申请。
4. 展示旧服务时长 `3.00`、新服务时长 `3.50`，以及申请原因。
5. 在“审核说明”中输入：`现场情况属实，同意补充服务时长。`
6. 点击“通过并应用更正”。
7. 等待提示“更正申请已通过并应用”。

讲解词参考：

> v4 版本补齐了服务记录更正闭环。管理员审核通过后，系统会更新原服务记录，并按服务时长差额调整志愿者积分；如果驳回，则原记录和积分都不会改变。这保证了服务档案既能纠错，又保留审核责任。

录制注意：

- 如果该申请已经被你前一次录制审核过，页面会显示“已通过”而不是按钮。重新执行 `demo-data.sql` 即可恢复待审核状态。

### 3.7 展示通知与外部任务，约 20 秒

操作步骤：

1. 点击“通知”。
2. 展示站内通知列表、未读数量。
3. 向下展示“外部通知任务”。
4. 指出邮件通道可配置真实 SMTP，短信通道当前为本地发送实现。

讲解词参考：

> 系统处理报名、审核、反馈等业务时，会生成站内通知，并尝试通过 WebSocket 实时推送。外部通知任务会记录邮件或短信发送状态、失败原因和重试次数；启用 SMTP 后，邮件可以真实发送，短信通道当前使用本地发送实现，后续可替换为真实短信服务商。

录制注意：

- 不建议在 3-4 分钟视频中现场配置 SMTP 或展示 `.env`。
- 可以不点击“重试”，只展示任务状态即可。

### 3.8 展示统计和审计，约 30 秒

操作步骤：

1. 点击“统计”。
2. 展示“用户总数、活动总数、报名总数、累计服务时长、捐赠总金额”等指标。
3. 展示“活动状态分布”“报名状态分布”“近 6 个月活动趋势”。
4. 不必真的点击“导出统计 CSV”，只说明可导出。
5. 点击“审计日志”。
6. 展示刚才的审核、更正等关键操作被记录。

讲解词参考：

> 管理员可以通过统计看板查看平台运行情况，包括活动、报名、服务时长、反馈、捐赠和故障处理等指标。关键管理动作会进入审计日志，例如报名审核、服务记录更正、内容审核和公告发布，方便后续追溯。

收尾讲解：

> 这个演示覆盖了志愿者报名、后台审核、服务记录纠错、通知反馈、统计看板和审计追踪，说明系统已经形成从前台参与到后台治理的完整业务闭环。

## 4. 如果时间不够的删减方案

如果老师要求严格控制在 3 分钟以内，按下面顺序删减：

1. 删除“通知”页，只在服务记录更正后口头说明系统会生成通知。
2. 删除“统计”页中的趋势表，只展示上方统计卡片。
3. 删除“活动筛选”，直接找到“校园迎新志愿服务”点击报名。
4. 不演示“审计日志”的筛选，只打开页面展示最近记录。

不要删除的内容：

- 志愿者登录和报名。
- 管理员审核报名。
- 服务记录更正审核。
- 最后总结“业务闭环”。

## 5. 如果想录成更偏答辩风格

可以在开头多说 10 秒：

> 本系统采用前后端分离架构，前端使用 Vue 3，后端使用 Spring Boot，数据库使用 MySQL。样例数据通过 SQL 脚本导入，避免在生产环境默认写入测试账号。

可以在结尾多说 10 秒：

> 目前项目支持真实 SMTP 邮件接入，短信通道和支付确认保留本地实现，对象存储保留适配接口，后续接入真实第三方服务时不需要改动核心业务流程。

## 6. 录制时不要展示的内容

- 不要打开 `backend/.env`，里面可能有数据库密码或邮箱授权码。
- 不要展示 GitHub token、数据库管理工具密码、个人邮箱授权码。
- 不要现场执行 Maven 或 npm 构建，视频时间会被拖长。
- 不要现场修改数据库结构。
- 不要在视频中承诺“真实短信、真实支付已经接入”，当前准确说法是：真实 SMTP 邮件已支持配置接入，短信通道和支付确认仍保留本地实现或适配边界。

## 7. 推荐录制台词压缩版

如果你希望边录边念，可以按下面这版压缩台词走：

> 我们的系统面向志愿者服务管理，支持志愿者、组织方和管理员三类角色。现在先以志愿者林安登录，进入活动中心后可以按状态筛选正在报名的活动，并对校园迎新志愿服务提交报名。报名后，在我的报名页面可以看到状态进入待审核；服务结束后，服务记录会进入个人档案，如果时长或成果有误，可以提交服务记录更正申请。
>
> 接下来切换到管理员账号。管理员进入活动执行页面，选择校园迎新志愿服务，可以看到待审核报名、报名说明和自助签到码。点击审核通过后，报名状态完成流转。再进入服务记录页面，可以看到林安提交的服务记录更正申请，审核通过后系统会更新服务时长并调整积分。
>
> 系统还提供站内通知、外部通知任务、统计看板和审计日志。通知用于反馈审核结果，统计看板用于查看活动、报名、服务时长和捐赠情况，审计日志用于记录关键管理操作。这样就形成了从志愿者参与、后台审核、服务记录治理到统计审计的完整闭环。
