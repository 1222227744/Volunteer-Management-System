# 测试流程引导

本文档用于项目提交前、课堂验收前和演示环境重置后的人工测试。测试目标是确认前端页面、后端接口、数据库样例数据和当前文档描述保持一致。

## 1. 测试范围

本流程覆盖当前 v4 交付版本的主要闭环：

- 用户登录、角色权限和个人资料维护。
- 活动查询、报名、审核、签到码和报名状态流转。
- 服务记录查看、更正申请、管理端审核和积分调整。
- 内容投稿、公告通知、外部通知任务和 WebSocket 站内通知。
- 捐赠订单、支付结果确认和捐赠记录生成。
- 反馈处理、资源对接、荣誉激励、统计看板、审计日志和系统运维配置。
- 构建验证、接口冒烟和交付前清理。

不覆盖的内容：真实短信服务商、真实支付平台商户号、第三方对象存储账号联调。这些能力当前保留适配端口，真实联调属于后续扩展。

## 2. 测试前准备

确认本机具备以下环境：

| 软件 | 推荐版本 | 验证命令 |
| --- | --- | --- |
| JDK | 17 | `java -version` |
| Maven | 3.9+ | `mvn -v` |
| Node.js | 20 LTS | `node -v` |
| npm | 10+ | `npm -v` |
| MySQL | 8.0+ | `mysql --version` |

从项目根目录执行配置脚本，生成真实运行配置。

Windows：

```powershell
powershell -ExecutionPolicy Bypass -File scripts/setup-windows.ps1 -DbUser root -DbPassword "你的MySQL密码" -InitDb -WithDemo
```

Ubuntu：

```bash
bash scripts/setup-ubuntu.sh --db-user root --db-password '你的MySQL密码' --init-db --with-demo
```

如果不使用脚本，也可以手工执行：

```sql
SOURCE backend/src/main/resources/sql/init.sql;
SOURCE backend/src/main/resources/sql/demo-data.sql;
```

## 3. 启动验证

### 3.1 启动后端

```powershell
cd backend
mvn clean spring-boot:run
```

预期结果：

- 控制台显示 Spring Boot 启动成功。
- `http://127.0.0.1:8080/api/health` 返回成功响应。
- 没有数据库连接失败、迁移失败或端口占用错误。

### 3.2 启动前端

新开终端：

```powershell
cd frontend
npm install
npm run dev
```

预期结果：

- Vite 输出本地访问地址。
- 浏览器访问 `http://127.0.0.1:5173` 能打开登录页。
- 前端页面整体为红白灰后台风格，顶部导航和卡片样式显示正常。

## 5. 接口冒烟测试

使用支持 `.http` 文件的 IDE 或 REST Client 插件打开：

```text
backend/api-demo.http
```

建议顺序：

1. 执行健康检查。
2. 执行管理员登录，将响应中的 `data.token` 填入顶部 `@token`。
3. 查询活动列表，确认样例数据已导入。
4. 创建活动、报名、审核报名。
5. 创建捐赠订单，将响应中的 `data.id` 和 `data.callbackToken` 分别填入 `@orderId` 和 `@confirmToken`。
6. 执行支付结果确认，确认状态为 `PAID` 后再查询捐赠记录。
7. 查询外部通知任务并重试失败任务。
8. 查询统计看板、审计日志和系统配置。

预期结果：

- 普通 JSON 响应符合 `{ code, message, data }` 结构。
- 权限不足时返回明确错误，不暴露后端堆栈。
- 支付确认令牌错误时不能生成正式捐赠记录。
- 关键操作能在审计日志中查到。

## 6. 构建验证

交付前必须至少执行一次后端和前端构建。

后端：

```powershell
mvn -q -f backend/pom.xml -DskipTests package
```

前端：

```powershell
npm --prefix frontend run build
```

预期结果：

- 后端生成 `backend/target/volunteer-service-backend-0.0.1-SNAPSHOT.jar`。
- 前端生成 `frontend/dist/`。
- 构建完成后提交源码时不要把 `backend/target`、`frontend/dist`、`.env` 或上传文件目录提交到 Git。

提交前检查以下文档与代码口径一致：

| 文档 | 检查重点 |
| --- | --- |
| `README.md` | 启动、样例数据、构建、当前完成边界是否准确 |
